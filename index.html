Dominio 1 · Design and develop database solutions

Diseñar y desarrollar

M1Objetos de base de datos

  • Tipos: el más pequeño que alcance · decimal(p,s) para dinero · datetime2 mejor que datetime · nvarchar solo si necesitas Unicode.
  • Índices: clustered ordena la tabla (uno; casi siempre la PK) · nonclustered = estructura aparte · INCLUDE cubre la consulta · filtered indexa solo el WHERE. Columnstore = analítica; rowstore = OLTP.
TablaClaves
In-memoryMEMORY_OPTIMIZED = ON · DURABILITY = SCHEMA_AND_DATA (default) o SCHEMA_ONLY (se pierde al reiniciar)
Temporal2 columnas datetime2 + PERIOD FOR SYSTEM_TIME + SYSTEM_VERSIONING = ON
Ledgeractualizable: SYSTEM_VERSIONING = ON, LEDGER = ON · solo INSERT: LEDGER = ON (APPEND_ONLY = ON)
Externalsolo metadatos: EXTERNAL DATA SOURCE + EXTERNAL FILE FORMAT + EXTERNAL TABLE. Preview en Azure SQL DB y Fabric; GA en SQL Server 2025
GraphAS NODE / AS EDGE + MATCH
  • JSON: tipo json (o nvarchar(max) + ISJSON()). Índice: CREATE JSON INDEX (solo columnas json) o columna calculada con JSON_VALUE + índice normal.
  • Constraints: PK (único, sin NULL) · FK (ON DELETE CASCADE | SET NULL | NO ACTION) · UNIQUE (admite un NULL) · CHECK · DEFAULT.
  • SEQUENCE: objeto propio, no atado a una tabla (a diferencia de IDENTITY): se comparte y se pide antes del INSERT.
  • Partitioning: partition function (límites) → scheme (filegroups) → tabla ON scheme(col). RANGE LEFT: el límite queda en la partición izquierda; RIGHT: en la derecha.

M3T-SQL avanzado

  • CTE: WITH x AS (…). Recursiva = ancla + UNION ALL + miembro recursivo; OPTION (MAXRECURSION n) (default 100; 0 = sin límite).
  • Window: fn() OVER (PARTITION BY … ORDER BY …): ranking (ROW_NUMBER RANK DENSE_RANK), vecinos (LAG LEAD), acumulados (SUM() OVER).
  • Graph: WHERE MATCH(a-(arista)->b); camino más corto: MATCH(SHORTEST_PATH(a(-(e)->b)+)) con FOR PATH en el FROM.
  • Correlacionadas: la subconsulta usa columnas de la externa · EXISTS · CROSS APPLY / OUTER APPLY = por fila.
  • Errores: TRY…CATCH · THROW (moderno; THROW; re-lanza el original; error propio ≥ 50000; la sentencia anterior debe terminar en ;) vs RAISERROR · SET XACT_ABORT ON · XACT_STATE().

  • Always Encrypted: Deterministic (mismo valor → mismo cifrado; permite =, JOIN, GROUP BY) vs Randomized (más seguro; sin comparaciones). Con enclave seguro: LIKE y rangos. La CMK (p. ej. Key Vault) cifra la CEK; el cliente usa Column Encryption Setting=Enabled.
  • DDM: default() email() random() partial() (y datetime() desde 2022); UNMASK ve el dato real. No es un control fuerte.
  • RLS: función inline + CREATE SECURITY POLICY. FILTER PREDICATE limita lo que se lee; BLOCK PREDICATE impide escribir filas no permitidas.
  • Permisos: GRANT / DENY / REVOKE; DENY gana. Roles, mínimo privilegio, permisos a nivel de esquema.
  • Passwordless: CREATE USER [x] FROM EXTERNAL PROVIDER · Authentication=Active Directory Managed Identity (user-assigned: User ID=<client_id>) o Active Directory Default.
  • Auditing: SQL Server Audit (server audit + audit specification) · Azure SQL Auditing → Storage, Log Analytics o Event Hubs.
  • Endpoints de modelos: DATABASE SCOPED CREDENTIAL con IDENTITY = 'Managed Identity' (código en M9); rol Cognitive Services OpenAI User; permiso EXECUTE ON EXTERNAL MODEL.
  • Endpoints DAB (REST / GraphQL / MCP): authentication.provider = "EntraID" (por defecto Unauthenticated → todo es anonymous) · permisos por rol y acción en cada entidad · host.mode = production. El endpoint MCP usa esos permisos.

M6Rendimiento

  • Tier: DTU = paquete simple · vCore = cómputo y almacenamiento por separado. General Purpose = uso general · Business Critical = baja latencia + réplica de lectura incluida · Hyperscale = hasta 128 TB, escala y restore rápidos · Serverless (GP e Hyperscale) = se auto-pausa.
  • Planes: actual vs estimated · Seek bueno, Scan sobre tabla grande malo · Key Lookup → INCLUDE · avisos de conversión implícita / missing index.
  • Query Store: historial de consultas y planes; Regressed Queries; sp_query_store_force_plan; hints sin tocar el código. QPI = vista del portal sobre Query Store.
  • DMVs: sys.dm_exec_requests (qué corre / quién bloquea) · dm_exec_query_stats (consumo acumulado) · dm_tran_locks · dm_os_wait_stats (esperas) · dm_db_missing_index_*.
  • Blocking = espera en cadena. Deadlock = ciclo; el motor mata una víctima (1205). Arreglo: transacciones cortas, mismo orden de acceso, buenos índices, RCSI, reintentos.

IA en la base de datos

25–30 % del examenM9Modelos y embeddingsM10BúsquedaM11RAG

M9Modelos y embeddings

  • Embedding = vector numérico que representa el significado, en una columna vector(n): n debe coincidir con el modelo y no se mezclan modelos.
  • Elegir modelo: small (barato, rápido) vs large (mejor calidad, más dimensiones) · multilingüe o multimodal solo si el caso lo pide · structured output = respuesta JSON fácil de procesar en T-SQL.
  • Qué incrustar: texto con significado (título + descripción + categoría); no IDs, fechas ni números sueltos.
  • Chunking: AI_GENERATE_CHUNKS(SOURCE = …, CHUNK_TYPE = FIXED, CHUNK_SIZE = n, OVERLAP = p): n en caracteres (no tokens), p = % de solapamiento (0–50).
  • Mantener embeddings al día: table trigger (simple, pero síncrono: alarga la transacción) · Change Tracking + Azure Functions o Logic Apps (asíncrono) · CDC / CES Preview (alto volumen o eventos). Foundry aloja el modelo; no detecta cambios.

Trampa: 3-large da 3,072 dimensiones y vector float32 admite 1,998: acórtalo con PARAMETERS '{"dimensions":1536}' o usa float16 (hasta 3,996).

M10Búsqueda inteligente

Full-textVectorHybrid
CuándoSKU, error, frase exactasignificado / sinónimosno sabes cómo busca el usuario; RAG
T-SQLCONTAINS FREETEXTVECTOR_DISTANCE VECTOR_SEARCHCONTAINSTABLE / FREETEXTTABLE + vector → RRF
  • Funciones: VECTOR_DISTANCE('cosine', a, b) (exacta) · VECTOR_SEARCH (aproximada, con índice) · VECTOR_NORMALIZE(v, 'norm2') · VECTORPROPERTY(v, 'Dimensions' | 'BaseType').
  • Métricas: cosine (la habitual para texto) · euclidean · dot (producto punto negativo: menor = más similar).
  • ENN (VECTOR_DISTANCE): exacta, recall 100 %, recorre todo → menos de ~50,000 vectores o filtros selectivos. ANN (VECTOR_SEARCH + CREATE VECTOR INDEX, DiskANN): recall < 100 %, rápida → cientos de miles o más. Preview en SQL Server 2025; GA en Azure SQL DB y Fabric.
  • RRF (Reciprocal Rank Fusion): suma 1/(k + rank) de cada lista (RANK de CONTAINSTABLE + rank vectorial), k = 60; sin normalizar scores.
  • Rendimiento: mide el recall de ANN contra ENN con las mismas consultas; en híbrida compara full-text, vector e híbrido, y ajusta k y pesos.
