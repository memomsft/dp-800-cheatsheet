Domain 1 · Design and develop database solutions

Design and develop

Database objects, programmability, advanced T-SQL and AI-assisted tools.

35–40 % of the examM1ObjectsM2ProgrammabilityM3Advanced T-SQLM4AI tools

M1Database objects

  • Types: the smallest that fits · decimal(p,s) for money · datetime2 over datetime · nvarchar only if you need Unicode.
  • Indexes: clustered orders the table (one; almost always the PK) · nonclustered = separate structure · INCLUDE covers the query · filtered indexes only the WHERE rows. Columnstore = analytics; rowstore = OLTP.
TableKey points
In-memoryMEMORY_OPTIMIZED = ON · DURABILITY = SCHEMA_AND_DATA (default) or SCHEMA_ONLY (lost on restart)
Temporal2 datetime2 columns + PERIOD FOR SYSTEM_TIME + SYSTEM_VERSIONING = ON
Ledgerupdatable: SYSTEM_VERSIONING = ON, LEDGER = ON · INSERT-only: LEDGER = ON (APPEND_ONLY = ON)
Externalmetadata only: EXTERNAL DATA SOURCE + EXTERNAL FILE FORMAT + EXTERNAL TABLE. Preview in Azure SQL DB and Fabric; GA in SQL Server 2025
GraphAS NODE / AS EDGE + MATCH
  • JSON: json type (or nvarchar(max) + ISJSON()). Index: CREATE JSON INDEX (json columns only) or a computed column with JSON_VALUE + a regular index.
  • Constraints: PK (unique, no NULL) · FK (ON DELETE CASCADE | SET NULL | NO ACTION) · UNIQUE (allows one NULL) · CHECK · DEFAULT.
  • SEQUENCE: standalone object, not tied to a table (unlike IDENTITY): it is shared and requested before the INSERT.
  • Partitioning: partition function (boundaries) → scheme (filegroups) → table ON scheme(col). RANGE LEFT: the boundary value stays in the left partition; RIGHT: in the right one.

M3Advanced T-SQL

  • CTE: WITH x AS (…). Recursive = anchor + UNION ALL + recursive member; OPTION (MAXRECURSION n) (default 100; 0 = unlimited).
  • Window: fn() OVER (PARTITION BY … ORDER BY …): ranking (ROW_NUMBER RANK DENSE_RANK), neighbors (LAG LEAD), running totals (SUM() OVER).
  • Graph: WHERE MATCH(a-(edge)->b); shortest path: MATCH(SHORTEST_PATH(a(-(e)->b)+)) with FOR PATH in the FROM.
  • Correlated queries: the subquery uses columns from the outer query · EXISTS · CROSS APPLY / OUTER APPLY = per row.
  • Errors: TRY…CATCH · THROW (modern; THROW; re-raises the original; custom error ≥ 50000; the previous statement must end with ;) vs RAISERROR · SET XACT_ABORT ON · XACT_STATE().

M4AI tools

Domain 2 · Secure, optimize, and deploy database solutions

Security, performance and deployment

Encryption and access, performance and concurrency, CI/CD with SQL Database Projects, and Azure services.

35–40 % of the examM5SecurityM6PerformanceM7CI/CDM8DAB and Azure

M5Security and compliance

TechniqueProtects against…
Always EncryptedDBA and cloud operator: the engine never sees the data in clear text
Cell-level (ENCRYPTBYKEY)reading the column without the key (the server decrypts)
TDEstolen files and backups (encrypts at rest)
DDMexposure in query results (it only masks, it doesn’t encrypt)
RLSseeing other users’ rows (multi-tenant)
  • Always Encrypted: Deterministic (same value → same ciphertext; allows =, JOIN, GROUP BY) vs Randomized (more secure; no comparisons). With a secure enclave: LIKE and ranges. The CMK (e.g. in Key Vault) encrypts the CEK; the client uses Column Encryption Setting=Enabled.
  • DDM: default() email() random() partial() (and datetime() since 2022); UNMASK shows the real data. It is not a strong control.
  • RLS: inline function + CREATE SECURITY POLICY. FILTER PREDICATE limits what is read; BLOCK PREDICATE prevents writing disallowed rows.
  • Permissions: GRANT / DENY / REVOKE; DENY wins. Roles, least privilege, schema-level permissions.
  • Passwordless: CREATE USER [x] FROM EXTERNAL PROVIDER · Authentication=Active Directory Managed Identity (user-assigned: User ID=<client_id>) or Active Directory Default.
  • Auditing: SQL Server Audit (server audit + audit specification) · Azure SQL Auditing → Storage, Log Analytics or Event Hubs.
  • Model endpoints: DATABASE SCOPED CREDENTIAL with IDENTITY = 'Managed Identity' (code in M9); role Cognitive Services OpenAI User; permission EXECUTE ON EXTERNAL MODEL.
  • DAB endpoints (REST / GraphQL / MCP): authentication.provider = "EntraID" (the default is Unauthenticated → everything is anonymous) · permissions per role and action on each entity · host.mode = production. The MCP endpoint uses those permissions.

M6Performance

  • Tier: DTU = simple bundle · vCore = compute and storage separately. General Purpose = general use · Business Critical = low latency + built-in read replica · Hyperscale = up to 128 TB, fast scale and restore · Serverless (GP and Hyperscale) = auto-pauses.
  • Plans: actual vs estimated · Seek good, Scan on a large table bad · Key Lookup → INCLUDE · implicit-conversion / missing-index warnings.
  • Query Store: history of queries and plans; Regressed Queries; sp_query_store_force_plan; hints without touching the code. QPI = portal view over Query Store.
  • DMVs: sys.dm_exec_requests (what is running / who blocks) · dm_exec_query_stats (cumulative cost) · dm_tran_locks · dm_os_wait_stats (waits) · dm_db_missing_index_*.
  • Blocking = chained wait. Deadlock = cycle; the engine kills a victim (1205). Fix: short transactions, same access order, good indexes, RCSI, retries.

M8DAB and Azure services

  • Data API builder = REST + GraphQL API (and MCP) over tables, views and stored procedures, no code. CLI: dab init, dab add, dab start.
  • Per entity: source (table | view | stored-procedure) · permissions (role + actions) · relationships (GraphQL) · cache (enabled, ttl-seconds). Pagination: default-page-size 100 · max-page-size 100,000.
  • Queries: REST $filter $orderby $select $first $after · GraphQL filter orderBy first after.
  • Hosting: container (Container Apps, App Service, ACI, AKS). Monitoring: Application Insights (app telemetry) + Log Analytics (DB logs and metrics via diagnostic settings).

Domain 3 · Implement AI capabilities in database solutions

AI in the database

Models and embeddings, intelligent search (full-text, vector, hybrid) and RAG with T-SQL.

25–30 % of the examM9Models and embeddingsM10SearchM11RAG

M9Models and embeddings

  • Embedding = numeric vector that represents meaning, in a vector(n) column: n must match the model, and models are not mixed.
  • Choosing a model: small (cheap, fast) vs large (better quality, more dimensions) · multilingual or multimodal only if the case needs it · structured output = JSON response that is easy to process in T-SQL.
  • What to embed: text with meaning (title + description + category); not IDs, dates or loose numbers.
  • Chunking: AI_GENERATE_CHUNKS(SOURCE = …, CHUNK_TYPE = FIXED, CHUNK_SIZE = n, OVERLAP = p): n in characters (not tokens), p = overlap % (0–50).
  • Keeping embeddings up to date: table trigger (simple, but synchronous: it lengthens the transaction) · Change Tracking + Azure Functions or Logic Apps (asynchronous) · CDC / CES Preview (high volume or events). Foundry hosts the model; it doesn’t detect changes.

Trap: 3-large returns 3,072 dimensions and a float32 vector allows 1,998: shorten it with PARAMETERS '{"dimensions":1536}' or use float16 (up to 3,996).

M10Intelligent search

Full-textVectorHybrid
WhenSKU, error, exact phrasemeaning / synonymsyou don’t know how users search; RAG
T-SQLCONTAINS FREETEXTVECTOR_DISTANCE VECTOR_SEARCHCONTAINSTABLE / FREETEXTTABLE + vector → RRF
  • Functions: VECTOR_DISTANCE('cosine', a, b) (exact) · VECTOR_SEARCH (approximate, with an index) · VECTOR_NORMALIZE(v, 'norm2') · VECTORPROPERTY(v, 'Dimensions' | 'BaseType').
  • Metrics: cosine (the usual one for text) · euclidean · dot (negative dot product: lower = more similar).
  • ENN (VECTOR_DISTANCE): exact, 100 % recall, scans everything → fewer than ~50,000 vectors or selective filters. ANN (VECTOR_SEARCH + CREATE VECTOR INDEX, DiskANN): recall < 100 %, fast → hundreds of thousands or more. Preview in SQL Server 2025; GA in Azure SQL DB and Fabric.
  • RRF (Reciprocal Rank Fusion): sums 1/(k + rank) from each list (the RANK from CONTAINSTABLE + the vector rank), k = 60; no score normalization.
  • Performance: measure ANN recall against ENN with the same queries; for hybrid, compare full-text, vector and hybrid, and tune k and weights.

  • Use it when the data is private or changes, you need to cite sources, and you don’t want to retrain. Fine-tuning = stable knowledge baked into the model.
